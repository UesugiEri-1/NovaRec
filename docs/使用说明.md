# NovaRec 使用说明（Windows 桌面录屏）

版本：1.1.1 ｜ 平台：Windows 10/11 x64 ｜ 最后更新：2026-11-08

NovaRec 是一款基于 Electron + Chromium 桌面采集（Desktop Capture / DXGI Duplication）的 Windows 录屏工具，支持**屏幕 / 区域 / 窗口**三种录制模式，可同时录制系统声音与麦克风，支持暂停继续、倒计时、素材库管理与**在线检查更新**。

v1.1.1 主要变化（修复版，功能与体积不变）：产物改为「启动器 + 应用」双文件结构，彻底解决部分机器上双击后进程立即退出、无窗口无提示的问题——外层 NovaRec.exe 是约 115 KB 的 C# 启动器，自动附加所需启动参数后拉起同目录的 NovaRecApp.exe；双击、桌面快捷方式、便携 exe 均无需任何手工参数。

v1.1.0 主要变化：安装包体积从 128 MB 降到约 97 MB、便携包从 421 MB 降到 285 MB，另提供约 96.7 MB 的单文件便携 exe；收尾不再依赖 ffmpeg.exe（改为内置纯 JS 快速重封装，毫秒级）；起录延迟（倒计时结束后到真正开录）从约 280 ms 降到 5–16 ms；窗口可见时间从约 1.2 s 提前到约 0.3–0.4 s；新增自动更新（GitHub 直连 + 镜像降级）。

---

## 一、功能一览

- 三种模式：整屏录制、矩形区域录制、单个应用窗口录制
- 输出格式：MP4（H.264 + AAC，兼容性最好，推荐）或 WebM（VP9 + Opus，体积更小，但低端 CPU 上编码开销明显更大）
- 音频：系统声音（默认播放设备 loopback）+ 麦克风（可分别开关，可同时录制并在采集端混音）
- 录制控制：倒计时（关闭 / 3 秒 / 5 秒）、暂停 / 继续、全局快捷键 F9（停止）、F10（暂停/继续）
- 界面：无边框浅色中文界面，白底 + 单一绿色强调色（类似杀毒软件的清爽风格），顶部标签栏切换录制/素材库/设置，底部状态栏显示版本与「打开保存目录」；圆角克制（容器方角、控件 2px）；托盘常驻，关闭主窗口只隐藏到托盘
- 图标：绿色 squircle 底 + 白色准星标记（四段弧环 + 四向刻度 + 中心点），与界面配色一致；托盘为白色单色线稿，录制中切换为红点状态
- 素材库：自动收录录制结果（缩略图、分辨率、时长、大小），支持播放、定位文件、删除
- 自动更新：设置页可检查更新（GitHub Release 直连，失败自动切换镜像与仓库 version.json），下载后由用户确认安装
- 单实例运行：同一数据目录只允许一个实例，重复启动会激活已有窗口

## 二、系统要求

- 操作系统：Windows 10 64 位（本机在 Windows 10 交互桌面实测）或 Windows 11 x64
- 显卡：支持 Windows 桌面复制（DXGI Desktop Duplication）的显卡（本机 AMD Radeon Vega 6 实测通过；无独显的核显一般也支持）
- 显示器：任意分辨率；支持系统缩放 100%–200%（本机 125% 缩放、物理 1920×1080 实测通过）
- 内存：建议 4 GB 以上
- 磁盘：1080p30 高清约 6–8 Mbps，每分钟约 45–60 MB；WebM 通常更小
- 打包版已内置 Electron 45（Chromium 156）运行时，**无需安装 Node.js / ffmpeg**；收尾（封装/封面/校验）由内置的纯 JS 重封装器完成

## 三、启动方式

### 3.1 安装包版（Setup.exe，推荐普通用户）

交付文件 `NovaRec-Setup-1.1.1-x64.exe`（约 97 MB，NSIS 安装包，LZMA 最大压缩；签名说明见第十二节）。

安装步骤：

1. 双击 `NovaRec-Setup-1.1.1-x64.exe`
2. 首屏「安装选项」保持默认的「仅为我安装」（当前用户，无需管理员），点「下一步」
3. 「选择安装位置」页可修改安装目录，点「安装」开始复制文件（约 40–60 秒）
4. 完成后可勾选「运行 NovaRec」直接启动，也可以双击桌面/开始菜单中的 NovaRec 快捷方式
5. 卸载：Windows 设置 → 应用 → 已安装的应用 → 「NovaRec 录屏」→ 卸载；或运行安装目录下的 `Uninstall NovaRec.exe`

安装包特性：

- 安装范围：默认仅当前用户（无需管理员）；首屏选择「为使用这台电脑的任何人安装」会请求 UAC 提权
- 默认安装目录：`%LOCALAPPDATA%\Programs\NovaRec`（可在向导第 3 步修改）；用户数据保存在安装目录下的 `NovaRecData`
- 安装位置自动兜底（v1.1.1）：安装器启动时会先探测默认目录能否真正写入；若被安全软件拦截（表现为目录建不出来、或装完 0 个文件），会**自动把安装位置改成 `D:\NovaRec`** 并在向导里显示，无需手工指定。若你的机器没有 D 盘，请在向导第 3 步改到其它可写位置
- 默认创建桌面快捷方式与开始菜单项（运行卸载程序时会一并清理）
- 安装包与便携版功能完全一致，只是安装位置与快捷方式管理方式不同

静默安装（批处理/部署用）：

    NovaRec-Setup-1.1.1-x64.exe /S /currentuser /D=D:\NovaRec

> 注意：`/D=<绝对安装路径>` **必须是最后一个参数且不能加引号**。部分安全软件（HIPS）会拦截安装程序写入系统盘，表现为静默安装返回成功但 0 个文件落地；遇到这种情况请把安装位置改到非系统盘，或直接使用下一节的便携版。

### 3.2 便携版（zip，免安装，推荐经常使用）

1. 解压交付包：NovaRec-1.1.1-win32-x64.zip（约 129.7 MB）；**请解压到非系统盘（如 D 盘）**，本机安全软件会拦截未签名程序写 C 盘，解压在 C 盘会导致无法保存设置/录像
2. 进入解压出的 NovaRec-win32-x64 文件夹，双击 NovaRec.exe
3. 首次运行若出现 Windows SmartScreen / 杀毒软件提示，选择「更多信息 → 仍要运行」或将文件加入信任（程序已带自签名证书，但该证书不在 Windows 受信任根证书列表内，因此仍会提示"未知发布者"，属正常现象，见第十二节）
4. 数据目录：与 exe 同级的 NovaRecData 文件夹（保存设置与素材库 library.json）。这是便携式布局，移动程序时请把整个文件夹一起移动

### 3.3 单文件便携版（Portable.exe，下载最方便）

1. 直接运行交付文件 NovaRec-Portable-1.1.1-x64.exe（约 96.7 MB），无需解压、无需安装
2. v1.1.1 起改为**自解压到 portable exe 所在目录**下的 `.novarec-portable` 再运行（不再依赖 %TEMP%），启动比 zip 版慢约 2–5 秒；退出后该临时目录自动清理。因此请把 portable exe 放在**非系统盘（如 D 盘）**的可写目录；若放在 C 盘，会自动回退解压到 `D:\NovaRecPortable-tmp`
3. 数据目录同样跟随程序：若把 exe 放在可写目录，数据保存在同级的 NovaRecData 文件夹；临时目录被系统清理不影响录制文件（输出目录默认在「视频\NovaRec」）
4. 杀毒软件可能对自解压行为敏感，若被拦截请改用安装包或 zip 版
5. 因为解压目录与 exe 同盘，首次启动会比 zip 版多花 2–5 秒解压，之后每次启动都会重新解压（单文件版的固有代价）

### 3.4 关于启动参数与 --no-sandbox（v1.1.1 起自动处理）

v1.1.1 起，交付包里的 NovaRec.exe 是约 115 KB 的 C# **启动器**，真正的应用是同目录的 NovaRecApp.exe。启动器自动附加 --no-sandbox 与必要的 GPU 沙箱开关后拉起应用，并原样转发命令行参数，最后等待应用退出并返回其退出码（单文件便携版的自解压目录清理依赖这一点）。

- **为什么需要**：在部分 Windows 机器上，Chromium 沙箱初始化会让进程直接退出（STATUS_BREAKPOINT / 0x80000003），没有任何窗口与错误提示；NovaRec 完全离线、不加载远程页面，关闭沙箱不影响使用安全
- **所以**：双击 NovaRec.exe 即可，不需要手工加任何参数；安装包快捷方式、单文件便携 exe、zip 解压目录指向的都是这个启动器
- **命令行参数会被透传**：`NovaRec.exe --remote-debugging-port=9222` 等价于把参数传给 NovaRecApp.exe
- **排查启动问题**：双击无反应时，先看安装目录下是否生成了 launcher-error.log（启动器自身异常），再看 NovaRecData\dev.log（应用启动日志）

### 3.5 开发版（源码运行）

前提：已按 [构建文档](build.md) 完成依赖安装（Node.js 20+、`npm ci`、补装 Electron 二进制）。

bash（Git Bash / MSYS）：

    cd novarec
    npm start

PowerShell：

    cd novarec
    npm start

注意事项：

- 若环境变量 ELECTRON_RUN_AS_NODE 存在，Electron 会以纯 Node 模式运行、不显示窗口，启动前必须清除（Git Bash：`unset ELECTRON_RUN_AS_NODE`；PowerShell：`$env:ELECTRON_RUN_AS_NODE = $null`）
- 部分受限环境（虚拟机 / 企业策略）必须加 --no-sandbox 才能启动，用 `npm run start:nosandbox` 或设置 `NOVAREC_NO_SANDBOX=1`
- 开发版 userData 位于项目内 .data 目录（项目根/.data），素材库为 .data/library.json；删除 .data 可恢复默认设置
- 单实例锁按 userData 生效，同一数据目录只能跑一个实例

## 四、界面与三种录制模式

主界面顶部是标签栏：录制 / 素材库 / 设置，右侧显示 F9、F10 快捷键提示；底部是状态栏（版本号、打开保存目录按钮）。录制页上方是三种连体模式卡片（屏幕 / 区域 / 窗口），下方分为左右两列：左列是来源选择（屏幕缩略图或窗口列表）与「输出」区块（性能模式、保存位置），右列是「声音」与「画面」参数面板（系统声音、麦克风、帧率、画质、格式、倒计时）；页面底部是固定的操作条，右侧为绿色「开始录制」按钮。

### 4.1 屏幕录制（整屏）

1. 打开「录制」页，模式选「屏幕录制」（默认）
2. 在「选择屏幕」缩略图列表中点击要录制的显示器（多显示器时每块屏一张缩略图）
3. 设置参数：系统声音、麦克风（含设备选择）、帧率、画质、格式、倒计时、性能模式（见第十四节）；「保存位置」显示当前输出目录，可点「打开文件夹」
4. 点击「开始录制」（或托盘菜单「开始录制」），倒计时窗显示「即将开始录制」，倒计时结束自动开始（操作条此时切换为计时 + 暂停/停止按钮）
5. 录制中：开启「录制时隐藏主窗口」时主窗口自动隐藏，托盘图标切换为录制态；按 F10 暂停/继续，按 F9 停止（也可用主界面/托盘按钮）
6. 停止后自动处理视频（封装/转码 + 生成封面），提示「录制完成：文件名」，并自动打开素材库页

输出：原生画质下分辨率等于该显示器的物理分辨率（本机 1920×1080）；开启性能模式后采集与输出上限为 1280×720 / 30 fps（见第十四节）。

### 4.2 区域录制（矩形框选）

1. 模式选「区域录制」
2. 点击「选择区域」：屏幕变暗并出现框选覆盖层，按住鼠标左键拖动画出矩形，松开鼠标完成；按 Esc 取消；已选区域可点「清除」重选
3. 框选完成后显示区域尺寸，按屏幕模式的方式设置参数并开始录制

尺寸说明：框选坐标是 DIP（逻辑像素），视频按物理像素输出：**视频尺寸 = 区域 DIP 尺寸 × 系统缩放比例**（本机 125% 缩放下，800×600 的区域输出 1000×750 视频；宽高会取偶数）。

限制：区域不能跨显示器；框选范围超出所选显示器时会被裁剪（以区域中心点所在显示器为准）。

### 4.3 窗口录制（单个应用窗口）

1. 模式选「选择窗口」
2. 在窗口列表中点击目标窗口（列表为系统当前窗口的缩略图，支持刷新与搜索）
3. 开始录制

行为与限制：

- 只采集所选窗口的画面，窗口移动/缩放时画面跟随
- 部分窗口无法被桌面复制直接抓取（UWP 应用、部分硬件加速/受保护内容、DirectComposition 合成窗口等）。此时程序会**自动降级为区域裁剪**：录制该窗口所在的屏幕区域，可能录到窗口后面/周围的其他内容（状态会标记降级 fallback）
- 录制过程中窗口关闭，本次录制会失败/中断并提示错误
- 需要纯净画面时，建议改用「区域录制」或先把目标窗口最大化

## 五、快捷键与托盘

- F9：停止录制（倒计时阶段按 F9 可取消本次录制）
- F10：暂停 / 继续（暂停时间不计入视频时长）
- 全局快捷键仅在倒计时/录制/暂停期间注册，未录制时不会占用系统的 F9/F10
- 托盘菜单：显示 NovaRec 主界面 / 开始录制（固定为屏幕模式，沿用当前设置）/ 暂停（F10）/ 停止（F9）/ 打开保存目录 / 退出 NovaRec
- 关闭主窗口（右上角 ×）只是隐藏到托盘；要真正退出程序请用托盘菜单「退出 NovaRec」

## 六、设置页说明

| 设置项 | 说明 |
| --- | --- |
| 保存位置 | 视频输出目录，默认「视频\NovaRec」（C:\Users\<用户名>\Videos\NovaRec）；可更改、可打开文件夹 |
| 默认格式 | MP4（H.264 Baseline + AAC，兼容性最好）/ WebM（VP9 + Opus，体积更小，部分播放器不支持） |
| 画质 | 标准 / 高清 / 超清 三档（按分辨率×帧率估算码率：标准约 0.08、高清 0.15、超清 0.25 系数，码率限制在 1.5–16 Mbps） |
| 帧率 | 30 fps / 60 fps（60 fps 更流畅，文件更大、CPU 占用更高） |
| 性能模式 | 自动 / 开启 / 关闭，默认「自动」：低配电脑（≤4 核或 ≤8 GB 内存）自动启用 720p·30fps、画质封顶「标准」、码率约 4.5 Mbps，并关闭界面装饰动画；开启后帧率/画质会自动封顶（详见第十四节） |
| 倒计时 | 关闭 / 3 秒 / 5 秒 |
| 录制时隐藏主窗口 | 默认开启；开始录制时自动隐藏主窗口，避免把 NovaRec 自己录进画面 |
| 鼠标指针 | 程序默认包含鼠标光标（settings.showCursor 默认 true），当前界面未提供开关（见「已知限制」） |
| 版本更新 | 设置页「版本更新」卡片：手动检查、下载、立即安装、跳过此版本；默认启动 10 秒后静默检查（24 小时一次），可在设置中关闭自动检查 |

## 七、素材库

- 每次录制成功后自动加入素材库：封面缩略图、文件名、分辨率、时长、文件大小、录制时间
- 操作按钮：
  - 播放：用系统默认播放器打开视频
  - 在文件夹中显示：在资源管理器中定位该文件
  - 删除：二次确认后把视频文件移入系统回收站（可从回收站恢复）
- 记录保存在 userData 目录的 library.json；若手动移动/删除了视频文件，素材库中的播放/定位会失败，可删除该条目

## 八、输出文件与目录

- 默认输出目录：「视频\NovaRec」（即 C:\Users\<用户名>\Videos\NovaRec）
- 保存位置自动兜底（v1.1.1）：启动时会探测默认目录可写性；若被安全软件拦截（本机安全策略会拦截未签名程序写 C 盘），自动改用程序数据目录下的 `NovaRecData\recordings`（通常与程序同盘，非系统盘），并写进设置。录制收尾时若发现原目录突然不可写，也会改存到该备用目录并提示
- 文件名格式：NovaRec_年月日_时分秒.mp4 / .webm，例如 NovaRec_20261031_190259.mp4
- 同时生成同名 .jpg 封面（素材库缩略图）
- MP4：录制时直接编码为 MP4；停止后由内置纯 JS 重封装器补全时长/metadata 并做 faststart 优化，实测 10–30 ms（不再调用 ffmpeg，也不会转码，画质无损）
- WebM：录制时为 VP9/VP8 + Opus 的 WebM 分片；停止后用纯 JS 重建簇/Cues/时长索引，实测 10–60 ms，可正常拖动进度（不再调用 ffmpeg）
- 收尾整体耗时（含封面与入库）实测 37–104 ms；v1.0 的 ffmpeg 转封装/转码路径（0.5–3 s）已移除
- 打包版数据目录：exe 同级 NovaRecData（设置、素材库、临时录制文件）

## 九、从源码打包（开发/交付）

命令（在项目根目录执行）：

    node scripts\package.mjs

scripts/package.mjs 的实现要点（v1.1.0）：

- 使用 @electron/packager 20.3.0 的 API（不是 CLI）：dir=项目根、out 由 --out 指定、overwrite=true、platform=win32、arch=x64、name=NovaRec、appVersion 取 package.json（1.1.0）、icon=assets/icon.ico
- **asar 打包**：生产依赖为 0，所有代码打进 resources/app.asar（约 1.9 MB），不再解包 node_modules、不再内置 ffmpeg.exe
- ignore 排除：artifacts/、.data*、.electron-cache/、.etmp/、docs/、scripts/、.git；prune 裁剪 devDependencies（electron、packager、electron-builder、@ffmpeg-installer 都不会进包）
- 复用本地 Electron zip（项目 .electron-cache），不联网下载；不执行 npm install / rebuild
- 打包后自动瘦身（pruneAppDir）：locales 只留 zh-CN/en-US（删 53 个 pak，-47.7 MB）、删除 dxcompiler.dll（-24.6 MB，WebGPU 不用）；保留 vk_swiftshader/vulkan 软件光栅回退与 Chromium 许可证文本
- 打包后自动校验：NovaRec.exe 存在、resources/app.asar 存在且含 main.js/renderer/index.html/mp4remux.js/webmfix.js/mediafix.js、不存在 app.asar.unpacked、无 ffmpeg 依赖、无 dxcompiler.dll、保留 SwiftShader；报告写入 artifacts/build/packaging-report.json
- 参数：--out=DIR 指定输出目录（如 --out=artifacts/dist-v5）；--zip 校验通过后自动生成交付 zip 并用 tar -t 校验条目（NovaRec.exe、resources/app.asar、使用说明.md、无 app.asar.unpacked），同时把 docs/使用说明.md 复制进产物根
- 只校验已有产物（不重新打包）：node scripts\package.mjs --verify-only（可再加 --zip 重打交付 zip）

1. `node scripts/package.mjs --out=artifacts/dist-v8 --zip` —— 打包 + 瘦身 + 校验 + 生成 zip
2. `node scripts/make-installer.mjs --dir=artifacts/dist-v8/NovaRec-win32-x64 --out=artifacts/installer-v8` —— 用 electron-builder（prepackaged）生成中文 NSIS 安装包，compression: maximum

## 十、常见问题（FAQ）

**1. 打开程序后黑屏 / 白屏 / 窗口一片空白？**

- 首次启动需要 1–3 秒初始化（GPU/界面），稍等片刻
- 开发版必须确认已清除 ELECTRON_RUN_AS_NODE 并加 --no-sandbox
- 若界面仍空白，检查显卡驱动是否过旧；可尝试设置环境变量 NOVAREC_DISABLE_GPU=1（或命令行加 --disable-gpu）后重启
- 查看日志或终端输出中的错误信息

**2. 录出来的视频没有系统声音？**

- 系统声音录的是 Windows **默认播放设备**的输出。若该设备被静音或音量为 0，录到的就是静音（实测静音端点会得到约 -91 dB 的静音音轨）
- 录制前检查任务栏音量图标未被静音、音量不为 0；用其他播放器确认声音能正常外放
- 只支持默认输出设备：切换 HDMI/蓝牙/耳机后需要重新开始录制
- 若目标应用使用独占模式或 DRM 内容，可能无法被采集

**3. 窗口录制失败 / 画面不是想要的窗口？**

- 部分窗口（UWP、硬件加速、受保护内容、DirectComposition 窗口）无法被桌面复制直接抓取，程序会自动降级为「区域裁剪」，会把窗口后面的画面一起录进去
- 此时建议：最大化目标窗口后重试，或改用「区域录制」
- 窗口在录制中关闭也会导致本次录制失败

**4. 杀毒软件 / SmartScreen 提示风险？**

- 交付的 exe 已用自签名证书签名（SHA-256 + DigiCert 时间戳），但证书不在 Windows 受信任根证书列表内，SmartScreen 仍可能提示「未知发布者」，属正常现象；选择「仍要运行」或将文件加入杀软白名单即可（信任证书的方法见第十二节）
- 本机出现过火绒 HIPS 拦截安装程序写入 C: 盘的情况：安装包装到 C: 盘会失败，请改装到 D: 盘或使用便携版
- 请不要把压缩包当作加密文件，它只是普通 zip

**5. 125% 缩放下录出来的尺寸和框选的不一样？**

- 框选使用逻辑像素（DIP），视频按物理像素输出，因此 125% 缩放下 800×600 的框会得到 1000×750 的视频
- 这是有意行为：保证录制清晰度不因系统缩放而损失
- 屏幕录制固定输出显示器物理分辨率（如 1920×1080）

**6. 录制文件太大 / 保存太慢？**

- 降低画质档位与帧率（30 fps），或选择 WebM 格式
- 现在停止后只需毫秒级收尾，通常看不到「正在保存」提示；若长时间卡住，多为磁盘/杀软问题（见第 8 条）
- 确保输出目录所在磁盘有足够空间

**7. WebM 视频在部分播放器里打不开？**

- 请用支持 VP9 的播放器（Chrome/Edge、VLC、PotPlayer 等）
- 需要最大兼容性请选 MP4

**8. 停止后一直显示「正在保存视频…」或提示处理失败？**

- 收尾是纯 JS 毫秒级操作，正常不会久等；若提示处理失败，检查：磁盘空间是否充足、输出目录是否可写、临时文件是否被杀软隔离
- 反馈问题时请附上 userData\NovaRecData 下的 dev.log（其中会记录 remux 耗时与失败原因）

**9. F9 / F10 没反应？**

- 全局快捷键只在倒计时/录制/暂停期间注册，未录制时不生效
- 部分应用会占用 F9/F10，可改用主界面按钮或托盘菜单控制

**10. 素材库为空 / 一直显示「加载中」？**

- 素材库只显示录制成功的视频；若之前录制失败则不会出现
- 若刚启动时显示加载中，稍等；持续异常可删除 userData 下 library.json 后重启（素材库记录重建，不影响视频文件）
- 若视频文件被手动移动/删除，条目会失效

**11. 双击 exe 没反应 / 提示已有实例？**

- v1.1.1 已修复「双击后进程立即退出、无窗口无提示」的问题：外层 NovaRec.exe 是启动器，会自动补上必需的启动参数（原理见 3.4 节）。若你用的还是 1.1.0 或更早版本，请升级到 1.1.1
- 如果 1.1.1 仍然双击无反应，先看安装目录下的 launcher-error.log 与 NovaRecData\dev.log，再把这两个文件连同 winver 信息一起反馈
- 同一数据目录只允许一个 NovaRec 实例；重复启动会激活已运行的主窗口（可能在托盘里）
- 检查托盘图标，或任务管理器查看是否已有 NovaRec / NovaRecApp 进程残留

**12. 开发版启动报错（userData 锁 / 单实例）？**

- 确认没有残留的 electron.exe 进程占用同一 userData
- 项目内 .data 目录可删除后重建（仅测试用，会清空设置与素材库记录）
- 启动命令必须带 --no-sandbox 并清除 ELECTRON_RUN_AS_NODE

## 十一、已知限制

- 系统声音仅采集默认播放设备；端点静音时录到静音。不支持应用级分流、不支持多输出设备混音
- 系统声音与麦克风同时开启时在采集端实时混音，输出单音轨，无法后期分离
- 窗口录制依赖桌面复制（Desktop Capture）。部分窗口（受保护窗口或记事本等 Chromium 无法直接采集的窗口）无法直接采集时，NovaRec 会自动切换为「激活窗口 + 屏幕裁剪该窗口区域」的方式继续录制：此时请勿让其他窗口遮挡被录窗口、也尽量不要移动它，否则会录到遮挡物/背景（这是平台限制，不是程序缺陷）
- 区域录制按物理像素输出，且不支持跨显示器框选
- 鼠标指针始终录入，界面暂未提供开关
- 性能模式开启时采集分辨率上限 1280×720：区域录制从整屏 720p 源裁剪，区域越小输出像素越少（本机实测 800×600 DIP 区域输出 668×500）；窗口录制最宽 1280、最高 720。需要原始分辨率时请把性能模式改为「关闭」
- 画质/帧率仅提供预设档位（标准/高清/超清；30/60 fps），未提供自定义码率
- 无摄像头画中画、无剪辑/压缩工具、无直播推流、无计划录制
- 程序已签名（自签名证书，非商业 CA 证书）：Windows 未信任该证书时仍显示「未知发布者」，且无法抑制 SmartScreen 警告；对外正式分发建议购买商业代码签名证书后重新签名
- 本机环境（火绒 HIPS 等安全软件）会拦截未签名程序写入 C: 盘用户目录：安装到 C: 盘会失败（v1.1.1 安装器会自动改用 D:\NovaRec）、便携版解压到 C 盘会失败（已改为解压到 exe 同目录，放 D 盘即可）、默认「视频\NovaRec」输出目录不可写（已自动改用 NovaRecData\recordings）。根治办法：把 NovaRec 加入安全软件信任区，或关闭其「系统加固/文件保护」类规则
- zip 未加密
- 打包版为便携式布局，数据保存在 exe 同级 NovaRecData，移动或升级时请整体替换并保留该目录
- 托盘「开始录制」固定为屏幕录制模式（沿用当前设置）

## 十二、代码签名与信任说明

### 12.1 本版签名状态

- v1.1.1 的便携包与安装包在构建时**未配置代码签名**（构建环境没有可用的商业证书；v1.0 曾用本机自签名证书签名）
- 因此 Windows SmartScreen 可能提示「Windows 已保护你的电脑 / 未知发布者」：这是未签名程序的正常提示，选择「更多信息 → 仍要运行」即可
- 如需在本机用已有自签名证书补签（仅受控环境有意义，对外分发仍无法避免 SmartScreen 提示）：
  `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sign-release.ps1 -Paths artifacts\installer-v5\NovaRec-Setup-1.1.0-x64.exe`
  证书来自 `.certs\NovaRec-CodeSigning.cer`（Subject：`CN=NovaRec, O=NovaRec, OU=Desktop, C=CN`），脚本会调用 `Set-AuthenticodeSignature` 并输出校验状态

### 12.2 为什么 Windows 还提示"未知发布者"

自签名证书的根不在 Windows 受信任根证书列表中，因此 `Get-AuthenticodeSignature` 状态为 `UnknownError`，提示"已处理证书链，但终止于不受信任的根证书"。这不是签名失败，而是缺少证书信任链。要消除提示，需要：

1. 在**目标电脑**上把 `.certs\NovaRec-CodeSigning.cer` 安装到「受信任的根证书颁发机构」（会弹出 Windows 安全警告，需要手动点「是」）
2. 或购买商业 CA 代码签名证书重新签名（正式对外分发推荐；自签名证书也无法避免 SmartScreen 提示）

### 12.3 本机一键信任（可选）

在项目根目录打开 PowerShell 执行：

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\trust-cert.ps1 -Paths artifacts\NovaRec-Setup-1.0.0-x64.exe

脚本会把 `.certs\NovaRec-CodeSigning.cer` 装入当前用户的「受信任的根证书颁发机构」与「受信任的发布者」，并在弹出系统安全警告时等待你点「是」，随后验证签名状态。撤销信任：

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\untrust-cert.ps1

验证签名（不改系统状态）：

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-sign.ps1 -Paths artifacts\NovaRec-Setup-1.0.0-x64.exe

> 注意：信任自签名证书只在**本机/受控环境**有意义；分发给他人时对方仍需自行决定是否信任。正式发布请换用商业 CA 证书。

## 十四、体积与性能优化（v1.1.0）与老设备建议

### 14.1 体积优化（v1.1.0）

| 优化项 | 收益 | 说明 |
| --- | --- | --- |
| 移除内置 ffmpeg.exe，改用纯 JS 重封装器 | -61.5 MB | MP4/WebM 时长/索引/metadata 由 src/main/mp4remux.js、webmfix.js、mediafix.js 完成，不转码、不损失画质 |
| 语言包只保留中文/英文（删 53 个） | -47.7 MB | Electron 默认带 55 个 locales，界面只用 zh-CN/en-US |
| 删除 dxcompiler.dll（WebGPU 着色器编译器） | -24.6 MB | 应用不使用 WebGPU；已用「打包后三模式录制+系统声音」回归验证 |
| 依赖不再随包分发、asar 打包 | 文件数 86 → 19 | 生产依赖为 0（纯 JS 实现），打包后只有一个 app.asar |
| NSIS 安装包 LZMA 最大压缩 | 安装包 122 MB → 97 MB | electron-builder 的 compression: maximum |
| 排除未使用图标母版（icon-1024/512/128.png） | -1.2 MB | 仅生成图标用，运行期只用 icon.png / icon.ico / tray*.png |

结果：便携目录 421 MB → 285 MB；便携 zip 173 MB → 129.7 MB；安装包 122 MB → 97 MB；另提供 96.7 MB 单文件便携 exe（同功能、未砍任何录制能力）。

按体积效率评估，保留了 GPU 软件光栅回退组件（vk_swiftshader/vulkan，6.1 MB，保证显卡驱动异常或远程桌面机器也能启动界面）
与 Chromium 许可证文本（5.4 MB，合规必需）。

### 14.2 性能优化（v1.1.0）

- **两段式起录**：程序在倒计时期间就并行完成「建隐藏采集窗 → 加载采集页 → getUserMedia 建立采集流 → 准备裁剪画布/混音轨」，
  倒计时结束只创建 MediaRecorder 并开录。实测「倒计时结束 → 真正开录」从 256–284 ms 降到 5–16 ms（几乎无感知）。
- **收尾毫秒级**：纯 JS 重封装替代 ffmpeg，MP4 10–30 ms、WebM 10–60 ms，收尾整体（含封面、入库）37–104 ms。
- **性能模式**（自动 / 开启 / 关闭）：在采集入口直接请求 1280×720、30 fps、码率上限 4.5 Mbps，画质档位封顶「标准」，
  WebM 优先 VP8（老 CPU 编码更省），音频 96 kbps，分片 2 s；降采样在 Chromium 采集层完成，不额外增加 canvas 缩放开销。
- **自动判定**：CPU ≤4 核或内存 ≤8 GB 视为低配，自动开启性能模式（本机 4 核 / 13.9 GB → 自动开启）；可在设置中强制开/关。
- **界面精简（perf-lite）**：性能模式启用时关闭界面装饰动画与过渡，降低低端 GPU 合成开销。
- **阻止显示器休眠**：录制期间持有 powerSaveBlocker，长时间录制不会因息屏中断。
- **隐藏采集窗口回收**：停止录制后空闲 25 秒自动销毁隐藏的采集窗口，录制结束即释放内存。
- **主进程减负**：主窗口隐藏时不推送录制状态（重新显示时补发）；托盘图标/菜单按状态去重；屏幕/窗口源列表 800 ms 短缓存；
  封面图按「路径 + 修改时间 + 大小」缓存。
- **渲染层减负**：录制计时从每 500 ms 刷新改为每秒一次。

实测（4 核 Ryzen 3 3300U / Vega 6 / 13.9 GB / 1920×1080@125%，单次录制 10 秒）：

- 全屏 MP4 高清 1080p30：28.8 fps、掉帧 5.0%、单核 CPU 28%（整机约 7%）、GPU 进程 14%、渲染器 7.6%
- 区域 MP4 高清（输出 1600×900）：28.9 fps、掉帧 4.3%
- 窗口 MP4 高清（1004×754）：30.0 fps、掉帧 0%
- 性能模式 720p：28.9 fps、单核 26%
- WebM/VP9 1080p30：28.6 fps，但单核 CPU 56%（渲染器 45%）、内存多约 180 MB → 低端机建议用 MP4
- 1080p60：受硬件编码能力限制，本机实测 36 fps（掉帧 40.5%）→ 60 fps 选项保留，但低端机不推荐
- 主线程：事件循环延迟 p95 ≤2.6 ms、定时器抖动 ≤6 ms，录制时界面不卡

> 性能与体积的完整数据见 docs/perf-baseline.md。

### 14.3 怎么选

| 你的情况 | 建议 |
| --- | --- |
| 不确定 / 普通办公电脑 / 老笔记本 | 保持默认「自动」 |
| 录制时明显卡顿、风扇狂转、录像掉帧 | 手动改为「开启」 |
| 要录 1080p / 60 fps / 超清，或需要小区域的高清画面 | 手动改为「关闭」 |
| 只录操作演示、教程、会议记录 | 「开启」即可，720p 完全够用，文件也更小 |

> 注意：性能模式是用「降低采集分辨率」换性能，不是后期压缩。录完之后不会自动转码，画质上限在录制时就已确定。

### 14.4 在哪里设置

- 录制页右侧参数面板 →「性能」分组 → 性能模式：自动 / 开启 / 关闭，下方显示当前生效状态（如「已启用 · 720p · 30fps · 约 4.5 Mbps」）

## 十五、版本自动更新（v1.1.0 新增）

### 15.1 它怎么工作

- 入口：设置页 →「版本更新」卡片。显示当前版本，按钮为「检查更新」；有新版本时出现「下载并安装」与「跳过此版本」。
- 检查顺序（任何一步成功即停止，全部失败才提示「暂时无法获取更新信息」）：
  1. GitHub Releases API 直连：`api.github.com/repos/UesugiEri-1/NovaRec/releases/latest`
  2. 镜像前缀重试同一 API：`gh-proxy.com`
  3. 仓库根 version.json（raw.githubusercontent.com → gh-proxy 镜像 → jsDelivr）
- 每个渠道超时 8 秒；启动 10 秒后静默检查一次，之后 24 小时内不重复自动检查（手动检查不受限）。
- 发现新版本：显示版本号与更新说明；点「下载并安装」后下载安装包（优先匹配 `NovaRec-Setup-<版本>-x64.exe`），
  校验 Content-Length 完整；下载完成后由用户确认「立即安装」——程序退出并静默启动安装包覆盖安装（不静默安装、不自动重启）。
- 安全限制：只允许 https、只允许 GitHub/镜像白名单域名、只下载 .exe；不会在后台偷偷安装。

### 15.2 发布新版本（维护者）

方式 A（推荐）：在 GitHub 仓库开 Release，tag 用 `v1.1.1` 这类格式，上传安装包并把文件名写成 `NovaRec-Setup-<版本>-x64.exe`。

方式 B（没有 Release 时）：在仓库根放 `version.json`：

    {
      "version": "1.1.1",
      "notes": "修复若干问题",
      "url": "https://github.com/UesugiEri-1/NovaRec/releases/download/v1.1.1/NovaRec-Setup-1.1.1-x64.exe",
      "assets": [ { "name": "NovaRec-Setup-1.1.1-x64.exe", "browser_download_url": "https://.../NovaRec-Setup-1.1.1-x64.exe" } ]
    }

注意：jsDelivr 对仓库文件有缓存（新版本可能延迟数小时），所以优先用 Release。

### 15.3 已知限制

- 安装包未做代码签名：安装时 Windows 仍会提示未知发布者（见第十二节）。
- 更新为「下载完整安装包 → 覆盖安装」，没有增量更新；下载体积约等于安装包体积。
- 使用第三方镜像（gh-proxy / jsDelivr）时可用性取决于镜像服务；直连 GitHub 失败的机器会自动走镜像。
- 上游仓库目前还没有 Release/version.json 时，检查更新会提示「未找到发布版本信息」，这是正常状态。

相关实现与测试：`src/main/updater.js`、`docs/updater.md`、`scripts/test-updater.mjs`（33 项测试）。
